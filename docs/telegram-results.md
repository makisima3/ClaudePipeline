# Telegram → Избранное

Опциональная интеграция отправляет результаты задач в «Избранное» **вашего** аккаунта через Telegram Web и Playwright. Бот, `api_id`, ключи Telegram и платные сервисы не нужны. Базовый трекер работает без Playwright. Получатель всегда определяется из текущей авторизации: произвольные чаты и личные алиасы не поддерживаются.

## Подключение

Все команды выполняются **в папке скачанного AgentPipeline на компьютере, где работает сервер**, тем же Python, которым запускается трекер. Устанавливать что-либо на телефоне, кроме обычного Telegram, не требуется.

1. Установите дополнительные компоненты:

   ```text
   python -m pip install playwright
   python -m playwright install chromium
   ```

   Это отдельная установка только для Telegram. Системный Chrome/Edge и его личный профиль не используются. Для первой загрузки Chromium и работы Telegram нужен интернет.

2. Откройте **Настройки → Telegram → Инструкция → Войти по QR**. В Telegram на телефоне: **Настройки → Устройства → Подключить устройство**. Отсканируйте показанный QR. Он обновляется автоматически; ожидание входа — до пяти минут. Если страница открыта на том же телефоне, откройте её на ПК, чтобы сканировать экран ПК.

3. Для входа по номеру телефона, паролю двухэтапной проверки или если QR не появляется, нажмите **Отменить вход**, затем выполните на ПК:

   ```text
   python tools/telegram_web.py login --show
   ```

   Команда откроет отдельное окно Chromium. Войдите в свой аккаунт обычным способом. После успешного входа окно закроется само; на странице трекера нажмите **Проверить сессию**. Одновременно открывать этот профиль командой и кнопкой в трекере нельзя.

4. Дождитесь надписи **Авторизация проверена · получатель: Избранное**. Папка профиля сама по себе не означает, что вход выполнен. Нажмите **Тест в Избранное**, проверьте сообщение в своём Telegram. Настройки показывают время последнего успешного теста.

Для проверки сохранённого входа из терминала доступна команда `python tools/telegram_web.py check`; для теста — `python tools/telegram_web.py test`. После ручного входа состояние интерфейса обновляет кнопка «Проверить сессию».

## Выбор задач

- **Результаты в Telegram** над доской, у поля чата и в настройках — выбор этого устройства/браузера. При первом использовании на телефоне или планшете включён, на ПК выключен. Источник определяется интерфейсом по признакам мобильного браузера, а не средой агента и не шириной окна. Ручной выбор хранится в localStorage этого браузера для адреса трекера; очистка данных сайта сбрасывает его.
- При создании карточки выбор становится отдельным серверным флагом **Отправить результат в Telegram**. Он доступен в карточке и сохраняется независимо от последующих переключений общего выбора или устройства просмотра. Создание через чат и импорт тоже передаёт выбор устройства; при импорте можно изменить флаг у каждой найденной задачи.
- Явная просьба вроде «скинь результат в ТГ» включает отправку для этой задачи при выключенном общем выборе. Форма распознаёт распространённые формулировки; агент чата передаёт смысл через `telegram_notify=true` в `create_task`/`update_task`. Агент задачи также может учесть явную просьбу в `finish_task`. Отрицание «не отправляй в ТГ» не подписывает задачу.
- Общий переключатель не меняет старые задачи. Если вручную включить флаг уже завершённой задачи, у которой ещё не было доставки, трекер отправит сохранённый краткий итог. Материалы, которые прежний запуск не подготовил, так не появятся: для них верните задачу в работу с нужным указанием. Повторное включение флага после успешной доставки не посылает тот же результат снова.

До подключения аккаунта переключатели предлагают настройку. Флаг задачи при этом можно сохранить заранее: если задача завершится без настроенного Telegram, она останется выполненной, а доставка покажет отдельную ошибку. После подключения нажмите «Повторить доставку» в карточке.

## Что придёт

Краткий итог: что сделано и что проверено, плюс материалы, по которым понятен результат. О пройденных тестах агент пишет только после их реального успешного запуска. Для визуальных изменений, особенно игровых, ожидаются скриншоты. Короткое видео добавляется, если нужно показать движение/взаимодействие и его реально можно записать; оно не обязательно для каждой игровой задачи.

Сначала приходит текст с номером задачи, названием и проектом, затем подготовленные файлы отдельными сообщениями с подписями. Сейчас файлы отправляются как документы, в том числе изображения и видео. Полный технический отчёт остаётся в трекере. Краткий текст ограничен примерно 3500 символами вместе с заголовком; до 10 файлов, до 100 МБ каждый, до 300 МБ всего. В сообщениях есть служебная метка `[AP:…:номер части]` для проверки спорной доставки.

Агент передаёт готовый текст и пути к файлам при завершении. Трекер **сразу копирует** материалы в собственное локальное хранилище и доставляет после выхода агента. Временные файлы агента к этому моменту уже могут исчезнуть. Вкладку на телефоне или ПК можно закрыть; компьютер и сервер трекера должны продолжать работать. Выключенный переключатель выполнения новых задач не выключает уже поставленные доставки.

## Ошибки и повтор

Статус доставки находится в карточке отдельно от результата задачи. Обычная ошибка не возвращает выполненную задачу в работу: исправьте причину и нажмите **Повторить доставку**. Уже подтверждённые части пропускаются. Если выключить флаг задачи, ещё не начавшиеся части отправляться не будут; уже принятое Telegram сообщение отменить так нельзя.

При потере авторизации настройка покажет **Нужно войти заново**. Повторите QR или вход командой, проверьте сессию, затем повторите доставку нужной задачи. После перезапуска трекер заново проверяет ранее настроенную сессию; наличие браузерного профиля не считается подтверждением входа. После сетевой ошибки доступна та же проверка. При изменении интерфейса Telegram Web может потребоваться обновление интеграции.

Если процесс оборвался после нажатия «Отправить», нельзя достоверно сказать, принял ли Telegram сообщение. Тогда статус — **Нужно проверить Избранное**, автоматического повтора нет. Найдите часть с меткой, показанной в карточке:

- **Последняя часть получена** — подтвердить её и продолжить оставшиеся;
- **Её нет — повторить** — повторить эту часть после проверки; перед действием интерфейс напоминает о риске дубля.

Повторные события завершения и обычные перезапуски не создают новую доставку одного запуска. Новый запуск задачи с доработками создаёт новый результат. Telegram Web не предоставляет транзакции вместе с локальной БД, поэтому неоднозначный исход требует такой проверки вместо обещания безусловного «ровно один раз».

Если исходные материалы не существовали или превысили лимиты при завершении, задача всё равно готова, но доставка заблокирована ошибкой подготовки. Попросите агента подготовить корректные файлы, вернув задачу в работу; один повтор сетевой отправки отсутствующий файл не восстановит.

## Локальные данные

`data/telegram/profile/` — отдельная браузерная авторизация; `data/telegram/results/` — копии материалов; `data/telegram/qr.png` — только текущий QR, удаляется после входа/отмены/перезапуска; `data/telegram/job.json` — временное задание транспорту, удаляется после операции. Флаги задач, очередь, ошибки и подтверждённые части находятся в `data/tracker.db`. Вся `data/` исключена из git. При переносе своей установки сохраняйте её целиком; пути к скопированным вложениям в очереди относительные. Не передавайте `data/` другу: он скачивает чистый код и входит в **свой** аккаунт.

## Короткая инструкция агенту

Если задача подписана или пользователь явно просит результат в Telegram, подготовь краткий `telegram_text` и `telegram_files` в `finish_task`: что сделано и действительно проверено, для визуальных изменений — скриншоты; видео — если оно нужно и доступно. Не отправляй самостоятельно: сервер копирует файлы и доставляет после выхода. Пути могут быть абсолютными или относительными к папке проекта; файлы должны существовать при вызове. Явную просьбу можно передать как `telegram_notify=true`. Не включай отправку у посторонних задач. При отсутствии материалов честно укажи ограничение в тексте и отчёте.

Пример аргументов `finish_task`:

```json
{
  "summary": "Исправлена форма входа.",
  "report": "Описание изменений и реально выполненных проверок.",
  "telegram_text": "Исправлена форма входа. Проверено открытие на телефоне и ПК.",
  "telegram_files": ["output/login-mobile.png", "output/login-desktop.png"]
}
```

Транспорт использует [отдельный постоянный профиль Playwright](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch-persistent-context) и [загрузку файлов через браузер](https://playwright.dev/python/docs/input#upload-files). Обычным агентам устанавливать Playwright для доставки не нужно: его устанавливает владелец на стороне сервера один раз.
