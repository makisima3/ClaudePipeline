# Участие в ClaudePipeline

Спасибо, что хотите помочь. Пушить в репозиторий может только владелец, всё остальное — через Issues и Pull Request из форка.

## Сообщить о баге

Откройте [Issue](https://github.com/makisima3/ClaudePipeline/issues/new/choose) по шаблону «Баг»: что делали, что ожидали, что получили, коммит трекера (`git rev-parse --short HEAD`), ОС и версию Python. Если ошибка в сервере — приложите вывод из окна консоли или кусок `data/restart.log`. Перед отправкой уберите из логов личные пути, имена проектов и содержимое задач, если они не нужны для разбора.

## Предложить улучшение

Issue по шаблону «Предложение по улучшению»: какую проблему решает, как это видится в интерфейсе, есть ли альтернативы. Крупные изменения лучше сначала обсудить в Issue, чтобы не делать работу впустую.

## Прислать Pull Request

1. Сделайте форк и клонируйте его.
2. Создайте ветку от `main`: `git checkout -b fix/коротко-о-сути`.
3. Внесите изменения и проверьте их (см. ниже).
4. Отправьте ветку в форк и откройте Pull Request в `main` этого репозитория. Опишите, что меняется и как проверяли.

## Соглашения

Подробно — в [CLAUDE.md](CLAUDE.md) и [AGENTS.md](AGENTS.md), главное:

- **Ноль внешних зависимостей**: только стандартная библиотека Python 3.10+, без pip и npm.
- **Фронт без сборки**: чистые HTML, CSS и JS в `web/`, без фреймворков и CDN.
- **Тексты на русском**: интерфейс, ошибки API, промпты, комментарии в коде.
- Стиль как в соседних файлах: короткие функции, плотный код, редкие комментарии по делу.
- Изменили устройство проекта (модули, эндпоинты, таблицы БД, MCP-инструменты, файлы в `data/`) — обновите CLAUDE.md, AGENTS.md и разделы «Как устроено»/«Файлы» в README.md.
- Новые колонки БД — через миграцию в `db.py`: у пользователей база уже существует.

## Проверка

Автоматические тесты изолируют базу и не вызывают модели. Минимум перед PR:

```
python -m unittest discover -s tests -v
node --check web/app.js
```

Плюс запустите трекер и пройдите изменённый сценарий руками. Для проверок используйте отдельную копию трекера во временной папке на другом порту (`PIPELINE_PORT`), а не свою рабочую базу.

## Чего не коммитить

- `data/` — база, отчёты, логи, вложения (папка в `.gitignore`, но проверьте `git status`);
- личные данные: пути к своим проектам, токены, содержимое задач и чатов, скриншоты с реальными данными (скриншоты для README снимаются только на демо-данных).

## Свои правки и обновление

Встроенное обновление трекера делает только `git pull --ff-only` и откажет, если в вашем `main` есть свои коммиты или незакоммиченные изменения. Поэтому рабочий клон держите на чистом `main`, а свои доработки — в ветке или форке. Если хотите пользоваться своей версией постоянно, запускайте трекер из форка и подтягивайте изменения отсюда сами (`git pull upstream main`).

Реальный сквозной тест Codex: `python tests/live_codex.py` (использует подписку, создаёт отдельную копию и порт). Реальные тесты Claude сейчас исключены по просьбе владельца; для совместимости используйте заглушки.
